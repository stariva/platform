# Mobile UI: аудит и визуальная проверка

## До

Исходное приложение имело только вход по email и экран видеоурока за авторизацией. Вход был одной формой без графического акцента; тёмной темы по системной настройке не было. Главная, каталог, кабинет и профиль отсутствовали. Экран урока невозможно было снять без действующей сессии. Локальный API при проверке входа отвечал 502 на `forms/formToken`.

Снимки входа: [375×812 светлая](assets/mobile-audit-before/login-375x812-light.png), [375×812 тёмная](assets/mobile-audit-before/login-375x812-dark.png), [412×915 светлая](assets/mobile-audit-before/login-412x915-light.png), [412×915 тёмная](assets/mobile-audit-before/login-412x915-dark.png). Тёмный системный режим давал тот же светлый экран.

## После

Через Playwright MCP проверены главная, каталог, вход, избранное, профиль, карточка курса и кабинет на 375×812 и 412×915 в светлой и тёмной темах. Для кабинета использован мокированный ответ существующего `account.myCourses`; очная запись проверена в dev-режиме с `?demo-bookings=1`. Снимки лежат в `docs/assets/mobile-audit-after/` с именами `экран-размер-тема.png`.

Исправлено после осмотра: переполнение сетки каталога, сохранение прокрутки при переходе на детали, обрезание кнопки пустого состояния под нижней навигацией и горизонтальная прокрутка сегментов кабинета. Проверены открытие/закрытие фильтра, поиск и сброс, избранное, переключение темы и отсутствие горизонтального переполнения на 375 px.

Пределы проверки: полноценный вход не проверен, потому что локальный API недоступен; Android WebView не запущен из-за отсутствия `adb` и JDK 21. Очные билеты, отмена и напоминания требуют серверного контракта, перечисленного в `docs/API.md`.
