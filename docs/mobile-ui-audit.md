# Mobile UI: аудит и визуальная проверка

## Исходное состояние

Приложение имело вход по email и экран видеоурока. Главной, каталога,
кабинета и профиля не было. Снимки исходного экрана входа лежат в
`docs/assets/mobile-audit-before/`.

## Видеокурсы

Через Playwright MCP проверены главная, каталог, купленный курс, экран
покупки, видеотека и плеер на 375×812 и 412×915 в светлой и тёмной темах.
Для просмотра использован мокированный ответ API с курсом, прогрессом и
уроками. Снимки нового сценария имеют префикс `video-` в
`docs/assets/mobile-audit-after/`.

Проверены прямой переход из «Продолжить просмотр» в урок, список уроков,
ссылка покупки на конкретный курс и отсутствие горизонтального
переполнения. После осмотра исправлены ширина сегментов видеотеки и полоса
прокрутки категорий в тёмной теме.

Для проверки плеера создан временный 25-секундный MP4: воспроизведение,
пауза и переход на +10 секунд прошли, файл после проверки удалён.
Полноэкранный режим в Playwright не открылся: браузер вернул
`TypeError: not granted`; в нативном WebView его нужно проверить отдельно.
Реальное HLS-видео требует работающего сайта с видеоданными и
авторизованного курса. Android WebView локально не запущен: нет `adb`
и JDK 21. Локальный API для проверки полного входа также недоступен.
