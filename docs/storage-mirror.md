# Зеркало хранилища VK Cloud и переключение просмотра видео

Закрытый бакет мастер-классов (видео, HLS-нарезки, PDF — всё под `workshops/`)
дублируется во второе S3-совместимое хранилище — VK Cloud Hotbox
(`hb.ru-msk.vkcloud-storage.ru`). Ключи объектов в обоих бакетах одинаковые,
поэтому файл можно читать из любого, где он уже есть. Это позволяет:

- переключить **просмотр видеуроков** на VK Cloud, не трогая остальное
  (`STORAGE_VIDEO_READ_PROVIDER=vkcloud`);
- при необходимости быстро перевести **весь сайт** на VK Cloud
  (`STORAGE_PROVIDER=vkcloud`) и так же быстро вернуться обратно.

Публичный бакет с фото каталога не дублируется: его адреса хранятся в базе
данных товаров, и переключение — отдельная задача с миграцией ссылок.

## Переменные окружения

```dotenv
# VK Cloud (S3-совместимое, Hotbox). Ключи выдаёт VK Cloud, бакет создать заранее.
VK_S3_ENDPOINT=https://hb.ru-msk.vkcloud-storage.ru   # значение по умолчанию
VK_S3_REGION=ru-msk                                   # значение по умолчанию
VK_S3_BUCKET=stariva-workshops                        # имя вашего бакета
VK_S3_ACCESS_KEY_ID=…
VK_S3_SECRET_ACCESS_KEY=…

# Маршрутизация. Активное хранилище: сюда пишут загрузки (пресайны админки,
# заливка кусков воркером), отсюда читают материалы и чистит sweep.
STORAGE_PROVIDER=yandex          # yandex (по умолчанию) | vkcloud

# Отдельно просмотр видеуроков (HLS и исходники MP4). Не задано — как активное.
STORAGE_VIDEO_READ_PROVIDER=vkcloud
```

Переменные читают сайт (apps/web) и воркер через сайт; в бакет воркер ходит
только по подписанным ссылкам, ключей у него нет.

## Как устроена синхронизация

Задача Hatchet `workshop-storage-mirror` (каждый час в :20) зовёт процедуру
`jobs.storage.mirrorSync` на сайте. Сайт сверяет листинги `workshops/` обоих
бакетов и выдаёт пачку файлов: подписанное чтение из активного и подписанную
заливку в зеркало. Воркер копирует файлы потоком (без буферизации в памяти:
исходники до 4 ГБ) и снова спрашивает, пока зеркало не догонит активный бакет
или не выйдет бюджет прогона (40 минут). Идемпотентно: скопированное исчезает
из следующей пачки, повтор после сбоя ничего не дублирует.

Направление всегда «активное → второе»: после полного переключения
(`STORAGE_PROVIDER=vkcloud`) синхронизация продолжит копировать новые файлы уже
в Яндекс, так что обратное переключение останется безопасным.

Первая выгрузка идёт несколько прогонов по 40 минут. Чтобы догнать быстрее,
временно поднимите частоту cron в `apps/jobs/src/workflows/workshop-storage-mirror.ts`
и верните обратно, когда в логах воркера `remainingFiles` станет `0`.

## Порядок включения

1. Создать бакет в VK Cloud и выдать себе ключи (S3 Hotbox, регион ru-msk).
2. Задать переменные `VK_S3_*` в окружении сайта и воркера.
3. Настроить CORS нового бакета — без него браузер не пустит плеер за кусками:

   ```sh
   bun --env-file=.env packages/storage/src/scripts/set-bucket-cors.ts https://stariva.ru https://app.stariva.ru https://localhost capacitor://localhost
   ```

   Скрипт обновляет правила обоих настроенных бакетов (Яндекс и VK Cloud).
4. Дождаться, пока `workshop-storage-mirror` догонит активный бакет
   (`remainingFiles 0` в логах). Публичные фото каталога копировать не нужно:
   зеркало хранит только `workshops/`.
5. Включить просмотр видео из зеркала: `STORAGE_VIDEO_READ_PROVIDER=vkcloud`
   и перезапустить сайт. Дальше действует защита от частичного копирования
   (см. ниже): зрители уходят в VK Cloud постепенно, по мере отметок нарезок.

## Почему переключение просмотра безопасно

Нарезка уходит в зеркало не сразу, а после того, как синхронизация скопирует
её папку **целиком** — это фиксируется отметкой `video_renditions.
mirror_synced_at` (обновляется той же процедурой `mirrorSync`, сбрасывается при
новой готовой нарезке). Зритель получает HLS-пропуск только на то хранилище,
где нарезка лежит полностью; иначе — из активного. Иначе плеер упёрся бы в
недостающие куски посреди урока. Пропуск закрепляет хранилище на время
просмотра, поэтому досмотр не скачет между бакетами.

Для ненарезанных видео (свежая загрузка) сайт проверяет наличие исходника в
зеркале и при отсутствии отдаёт ссылку в активный бакет.

Чистка (`workshop-storage-sweep`) удаляет из зеркала заменённые видео и
нарезки по тем же правилам, что и в активном бакете, чтобы зеркало не
разбухало. Ошибки зеркала чистку активного не роняют.

1. Убедиться, что просмотр из VK Cloud уже работает и проверен.
2. Приостановить новые загрузки через пресайны админки и заливку HLS.
   Дождаться завершения уже начатых загрузок, включая выданные пресайны.
3. Повторно запускать синхронизацию до `remainingFiles 0`, пока загрузки
   остаются приостановлены.
4. Задать `STORAGE_PROVIDER=vkcloud` и убрать `STORAGE_VIDEO_READ_PROVIDER` —
   видео теперь читается из активного VK Cloud. Перезапустить сайт и воркера,
   затем возобновить загрузки.
5. Новые загрузки идут в VK Cloud, синхронизация копирует новое в Яндекс
   как запасное хранилище.

Для обратного переключения выполнить ту же последовательность: приостановить
новые пресайны админки и заливку HLS, дождаться начатых загрузок, повторять
синхронизацию до `remainingFiles 0`, затем задать `STORAGE_PROVIDER=yandex`
(плюс `STORAGE_VIDEO_READ_PROVIDER=vkcloud`, если нужен отдельный просмотр),
перезапустить сайт и воркера и возобновить загрузки.

В обоих направлениях ссылки, выданные до переключения, могут указывать на
прежний бакет до истечения срока действия. Ключи объектов не меняются;
отсутствие необходимости перезаливать объекты гарантируется только если
записи не попадали в окно переключения между финальной синхронизацией и
возобновлением загрузок.

## Что осталось на Яндексе

- публичные фото каталога, отзывов и чеков (`AWS_S3_PUBLIC_*`): адреса в базе;
- материалы PDF, письма с вложениями, админка — читают из активного
  хранилища, но файлы лежат в обоих (в копии на VK Cloud).
