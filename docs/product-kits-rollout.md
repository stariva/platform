# Выпуск подкатегории kits

## Условие публикации

До завершения проверок ниже все товары с `subcategory = 'kits'` должны оставаться черновиками. Ответственный за выпуск разрешает публикацию редакторам только после проверки работающей витрины и доступной ревизии для отката. Это операционный запрет: API не проверяет версию развёрнутой витрины. Он относится и к сохранению формы товара со статусом «На сайте», и к быстрому переключателю публикации.

## Порядок выпуска

1. Сохранить порядок из `.github/workflows/deploy.yml`: миграция БД перед выкаткой кода. Миграция 0057 только добавляет значение enum; сама по себе она не разрешает публикацию. Админка и витрина выкатываются независимо: готовность админки не означает готовность витрины.
2. Развернуть витрину с `kits` в `apps/web/src/lib/products.ts` и дождаться успешного `kubectl rollout status deployment/stariva -n stariva`. Пока есть старые поды без этой поддержки, публикация запрещена.
3. В тестовом окружении опубликовать синтетический набор в категории `interior`. Проверить на странице товара подпись «Наборы для творчества», а на `/catalog/interior` — одноимённый фильтр: он показывает набор и исключает товары других подкатегорий. Проверить также обычный товар и сброс фильтра. Повторить проверку на выбранном образе для отката.
4. Сохранить SHA проверенного образа витрины. Перед первой публикацией в production убедиться, что и текущая, и предыдущая ревизии `deployment/stariva` содержат эту поддержку: workflow автоматически выполняет `kubectl rollout undo` при подтверждённом сбое выкатки. Для первого выпуска поддержки выполнить следующий обычный деплой с сохранённой поддержкой, пока наборы ещё в черновиках; проверить историю ревизий и образы через `kubectl rollout history deployment/stariva -n stariva`. Порядок миграций и деплоя не менять.
5. Проверить фильтр на работающей production-витрине. Зафиксировать SHA текущего и резервного образов и результаты проверок в записи выпуска, затем разрешить редакторам публикацию. После публикации первого набора проверить его подпись и работу фильтра в production.

## Откат

Пока опубликован хотя бы один набор, откатывать витрину разрешено только на проверенный образ с подписью и фильтром `kits`. Если нужная старая версия их не содержит, подготовить исправленный образ на её основе с сохранённой поддержкой наборов. Не удалять `kits` из enum, валидаторов или списка подкатегорий при откате. Перед каждым последующим деплоем проверять совместимость предыдущей ревизии, на которую может сработать автоматический откат.

Если необходимо убрать поддержку наборов, сначала остановить их публикацию всеми редакторами, перевести все опубликованные наборы в черновики, убедиться в успешной ревалидации страниц и отсутствии наборов в публичном каталоге. Проверить отсутствие опубликованных наборов запросом:

```sql
SELECT count(*)
FROM public.products
WHERE subcategory = 'kits' AND status = 'published';
```

Только при результате `0` и проверенном обновлении публичных страниц допускается откат на витрину без поддержки наборов. Значение enum сохраняется для существующих черновиков; повторная публикация требует заново пройти условия выпуска.
